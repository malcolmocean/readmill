Readmill

Read any web page one sentence at a time, leave notes in the margin, and do it all with your feet.

As a dad of a newborn, sometimes I have my entire attention free, but no hands, because one is holding the baby and the other is holding a bottle. I got a foot pedal to control my computer, and then I built this tool to let me read a book using my feet. I figured I might as well hook it up to the whole internet, not just one book.

  • hacker tool: load-unpacked, not in the Web Store yet
  • Chrome, Arc, Brave, Edge
  • macOS · Linux
  • notes saved as files on your disk

One pedal steps to the next sentence. Another opens a comment box, which you can dictate into. Each note stays pinned beside the sentence it’s about, and it’s still there the next time you open the page. It works on any article, essay or doc.

Your notes aren’t kept in an account or a cloud. Each page gets a .json file and a readable .md copy in ~/notes/web-comments/, so you can grep them, edit them, sync them, or hand them to an AI.

Using it

KeyWhat it does
⌥ ⇧ R or the toolbar iconTurn Readmill on or off for this page
Tab / ⇧ TabNext / previous sentence
EnterComment on the highlighted sentence
Tab Enter in the boxSave. Tab again moves on to Cancel, then to Delete on any earlier notes.
click / double-clickPick a sentence / comment on it

Pages you’ve commented on turn Readmill on by themselves when you come back. If a page has changed so much that a sentence can’t be found, its note isn’t lost: it shows up under “unplaced” in the little status pill at the bottom right.

Installing

You’ll need Node.js and a Chromium-based browser. Then:

git clone https://github.com/malcolmocean/readmill.git
cd readmill
./install.sh
  1. install.sh registers a small storage script with every Chromium browser you have. To save notes somewhere other than ~/notes/web-comments, run it as READMILL_DIR=~/somewhere ./install.sh.
  2. Open chrome://extensions, turn on Developer mode, click Load unpacked, and choose the extension folder.
  3. Open an article and press ⌥ ⇧ R.

Why the install script? Browser extensions can’t write files to your disk. Instead Chrome starts the storage script whenever Readmill saves or loads, and it exits when it’s done, so you never run a server. If the script isn’t set up yet, notes wait in the browser and are written to disk once it is.

The foot pedal

I use a three-pedal PCsensor FootSwitch. This one and this one are different listings of products that work identically. Out of the box the pedals type a, b and c. A Karabiner-Elements rule turns them into these:

PedalSendsIn Readmill
tap aTabNext sentence. In the comment box, moves to Save, then Cancel.
hold c + tap a⇧ TabPrevious sentence
tap cEnterOpen the comment box, or press the focused button
tap bfn SpaceStart or stop dictation
double-tap cSpacePage down. The next a picks up from the top of the screen.
hold b + tap a⌘ TabSwitch apps (not Readmill, just handy)

For the voice-to-text I have fn Space wired up to Wispr Flow.

A comment without using your hands:

c open the box → b dictate → talk → b stop → a c save

Tap c once and Enter arrives about a quarter-second later, because the rule first waits to see whether it’s a double tap.

Setup on a new Mac

  1. Install Karabiner-Elements. Run brew install --cask karabiner-elements, or download it from karabiner-elements.pqrs.org.
  2. Grant permissions. On first launch, macOS will prompt you for two things:
    • Allow the driver extension under System Settings → General → Login Items & Extensions → Driver Extensions.
    • Turn on Input Monitoring for karabiner_grabber and karabiner_observer under Privacy & Security.
    • Karabiner won’t modify anything until both are approved. If something seems dead, these are the first thing to recheck.
  3. Enable the pedal. Plug it in, and in Karabiner’s Devices tab turn on Modify events for “FootSwitch (PCsensor)”.
  4. Clear simple modifications for the device. Remove any a→tab or c→enter entries under Simple Modifications, since those run first and would hide the raw keys from this rule.
  5. Generate and add the rule.
    • Paste the script below into the JavaScript generator and copy the JSON it outputs.
    • Go to Complex Modifications → Add your own rule, paste the JSON, and save.
    • If you had earlier versions of these rules, delete them so they don’t conflict.
  6. Check the app switcher binding. Make sure AltTab’s trigger is ⌘⇥ in its Preferences → Controls. If it isn’t, the native macOS switcher answers instead.
  7. Verify. Open EventViewer (from the Karabiner menu bar icon), hold B and tap A, and you should see left_command down followed by tab.

The pedal’s a/b/c output is its factory default, so it needs no configuration of its own. If you ever reprogram it with PCsensor’s utility, update the from keys to match. The timing constants at the top of the script are the knobs to tune: shorten DOUBLE_TAP_MS if Enter feels laggy, or lengthen it if double-taps get missed.

The Karabiner script

Also in the repo as pedal/footswitch.karabiner.js.

// ECMAScript 5.1 — paste into Karabiner-Elements' JavaScript generator
//
// PCsensor FootSwitch (default output: pedals send a / b / c)
//   a        tap  → tab
//   b        tap  → fn+space (dictation)
//            hold → command  (hold b, tap a repeatedly = cmd-tab cycling)
//   c        tap  → return (fires after a short double-tap window)
//            double tap → space
//            hold → shift    (hold b+c, tap a = cmd-shift-tab, reverse)

var DEVICE = {
  type: 'device_if',
  identifiers: [{ vendor_id: 13651, product_id: 45057 }]
};

var C_TAPPED = 'footswitch_c_tapped';
var ALONE_TIMEOUT_MS = 1000;   // max hold for a b/c press to still count as a tap
var DOUBLE_TAP_MS = 250;       // window for c's double tap (also enter's delay)

// Base manipulator: from a pedal key, any modifiers pass through, device-scoped.
// Keys in `spec` are merged on top (and override defaults, e.g. conditions).
function pedal(from, spec) {
  var m = {
    type: 'basic',
    from: { key_code: from, modifiers: { optional: ['any'] } },
    conditions: [DEVICE]
  };
  for (var k in spec) m[k] = spec[k];
  return m;
}

function main() {
  return {
    description: 'FootSwitch: a=tab, b=dictation/hold cmd, c=enter/double-tap space/hold shift',
    description_notes: [
      '- hold b + tap a: cmd-tab (repeat a to cycle)',
      '- hold b+c + tap a: cmd-shift-tab (reverse)',
      '- double-tap c: space'
    ],
    manipulators: [
      // a: tab (picks up any held pedal modifiers)
      pedal('a', { to: [{ key_code: 'tab' }] }),

      // b: command while held; dictation if tapped alone
      pedal('b', {
        to: [{ key_code: 'left_command', lazy: true }],
        to_if_alone: [{ key_code: 'spacebar', modifiers: ['fn'] }],
        parameters: { 'basic.to_if_alone_timeout_milliseconds': ALONE_TIMEOUT_MS }
      }),

      // c, second tap within window: space
      pedal('c', {
        to: [
          { key_code: 'spacebar' },
          { set_variable: { name: C_TAPPED, value: 0 } }
        ],
        conditions: [DEVICE, { type: 'variable_if', name: C_TAPPED, value: 1 }]
      }),

      // c, first press: shift while held; return if nothing follows
      pedal('c', {
        to: [
          { set_variable: { name: C_TAPPED, value: 1 } },
          { key_code: 'left_shift', lazy: true }
        ],
        to_delayed_action: {
          to_if_invoked: [
            { set_variable: { name: C_TAPPED, value: 0 } },
            { key_code: 'return_or_enter' }
          ],
          to_if_canceled: [{ set_variable: { name: C_TAPPED, value: 0 } }]
        },
        parameters: { 'basic.to_delayed_action_delay_milliseconds': DOUBLE_TAP_MS }
      })
    ]
  };
}
